# 0831 问题清单

## 问题一：S05—S10 前置表示是否应进入 Agent 检索主链

### 问题陈述

当前流程在执行 PubMed 检索前，先由 Codex 或用户制作 PICO，再经过状态导入、启发式拆词和固定规则拼装：

```text
原始问题
→ S05 制作 PICO
→ S06 decompose 导入状态
→ S07 plan-terms 清理问句并生成 term plan
→ S09 QueryBuilder 拼装
→ S10 生成多条 query/lane
```

后续方案拟由运行 Skill 的 Agent 直接阅读原始问题、用户约束和 PubMed 语法规则，生成多条检索路线。在此前提下，需要确认 S05 的 PICO 和 S07 启发式 `term_plan` 是否提供了稳定、不可替代的检索增益，还是构成有损且重复的中间表示。S06 仅负责导入数据，本身没有检索推理价值。

### 当前实现与风险

- `clean_natural_query` 删除 `What is`、`Does`、`Describe` 等句首框架，随后将整句交给 PubMed ATM。该清理可能减少无效词，也可能误删信息，效果尚未经过系统验证。
- PICO 对治疗、暴露、比较和结局明确的临床问题具有解释力，但 BioASQ 还包含 factoid、list、机制、定义和命名实体题。强制使用 PICO 可能制造并不存在的人群或结局边界。
- `TermPlanner` 使用停用词、短语长度和少量医学特例生成概念词，可能丢失稀有实体、别名和原始词序。
- 当前结构化 lane 大多来自同一份 `title_abstract_terms`，彼此常是逐级收紧关系。高度相关的 lane 会被 RRF 当作独立信号，可能重复放大同一结果。
- 查询过窄时，多个概念之间的 `AND` 会漏掉没有同时出现全部词的 gold；查询过宽时，大量 `OR` 会扩大候选集并把 gold 推到较深排名。

相关实现：

- `plugins/medlit-cli/medlit/pubmed/query.py:73-89`：`clean_natural_query`；
- `plugins/medlit-cli/medlit/pubmed/query.py:92-198`：`TermPlanner`；
- `plugins/medlit-cli/medlit/pubmed/query.py:201-291`：`QueryBuilder`；
- `plugins/medlit-cli/medlit/cli.py:126-190`：规划与构建命令入口。

### 已有观察

- `Describe RankMHC` 被 PubMed 翻译为 `describe* AND RankMHC`，返回 0 条；只搜索 `RankMHC` 时，唯一结果就是 gold PMID `39555889`。这支持轻量清理，但不能证明整套 PICO/term plan 有效。
- UCHL1 完整问句因额外包含 `disease`、`caused` 等约束返回 0 条；`UCHL1[Title/Abstract] AND heterozygous[Title/Abstract]` 可以使 gold PMID `35986737` 排到首位。
- GBM 缺氧练习表明，增加宽泛或答案相关词会改变 Best Match 排序；只保留问题中的核心概念反而能让 gold 更靠前。
- 16 题 smoke 中，legacy、raw、RRF 和 MeSH 路线表现差异明显，说明检索表示和融合都会影响结果，不能凭结构复杂度判断优劣。详见 `doc/medlit_r1_convergence_report.md`。

### Agent 直接构建 query 的约束

- query 只能使用原始问题、用户约束、公开术语资源和检索过程中正常获得的信息。
- 评测时不得读取 `gold_answer`、`ideal_answer`、gold snippets 或 gold 文献后反向补词。
- 每条 lane 必须声明目的，例如精确实体、同义词召回、自然语言 ATM 或显式用户过滤；不能只做无意义的字符串微调。
- Python 侧保留确定性的语法检查，验证 JSON 结构、lane ID、括号、引号、布尔操作符和字段标签，但不替 Agent 判断医学语义和相关性。
- 旧 `TermPlanner + QueryBuilder` 暂时保留为兼容入口和实验基线。

### BioASQ 适用性风险

[BioASQ benchmark 创建指南](https://www.bioasq.org/sites/default/files/PublicDocuments/BioASQ_D3.7-TutorialsGuidelines2ndVersion_final_0.pdf)要求专家提出反映真实工作需求的问题，再提供答案和支持材料，现有资料不支持将其直接描述为“根据给定论文反向出题”。但同一专家随后会检索并绑定相关文献，评审阶段还会将系统找到的新相关文献加入 gold，[BioASQ-QA 数据说明](https://pmc.ncbi.nlm.nih.gov/articles/PMC10042099/)确认了这一扩充过程。

因此需要验证 BioASQ 是否存在问题措辞与 gold 标题/摘要高度重合的偏差。若稀有实体和原词组合经常直接命中 gold，`[Title/Abstract]` 检索会天然占优，PICO、MeSH 和语义扩展在真实措辞不对齐场景中的价值可能被低估。该假设不能由个别案例直接确认。

### 评估方案

固定 Agent、提示词、query 数量、日期上限、每路深度和 RRF 参数，使用全新 `state.json` 比较：

| 组别 | Agent 可见输入 | 评估目标 |
|---|---|---|
| A | 原始问题与用户约束 | Agent 直接构造 query 的最低链路 |
| B | 原始问题 + 冻结 PICO | S05 的增量价值 |
| C | 原始问题 + 冻结 term plan | S07 的增量或信息损失 |
| D | 原始问题 + PICO + term plan | 完整前置链是否优于 A |
| E | 旧 `plan-terms + QueryBuilder` | legacy 确定性基线 |

主要指标包括 Recall@10/100/500、MAP@10、独有 gold、候选量、query 失败率、lane PMID 重合率、排名相关性和 Agent 输出稳定性。结果需要按题型、gold 文献数量、稀有实体以及问题与 gold 标题/摘要的词面重合度分层。

另做三项偏差检查：计算问题与 gold/non-gold 标题摘要的词面重合；使用语义相同但表面不同的改写问题复测；再用真实用户问题或其他生物医学检索集进行外部验证。

### 决策标准

- 若 PICO 或 term plan 在多个题型和外部数据上有稳定增益，则作为 Agent 的可选上下文保留。
- 若只对临床型问题有效，则按问题类型启用，不再作为所有问题的强制阶段。
- 若与原始问题相比无增益或稳定损害召回，则退出默认主链，仅保留为解释层或 legacy baseline。
- MeSH 的价值在问题二中单独评价，不与 PICO/term plan 的效果混合归因。

## 问题二：MeSH 候选生成与验证能力不足

### 问题陈述

S07 将普通概念词改成标题式大小写后作为 `mesh_terms`，S08 再通过 NCBI MeSH ESearch/ESummary 检查首选词或入口词的字面一致性。这只能证明字符串能够对应某条 MeSH 记录，不能证明其记录类型、问题语境和检索组合正确。

相关实现：

- `plugins/medlit-cli/medlit/pubmed/query.py:95-114`：生成 `title_abstract_terms` 和 MeSH 候选；
- `plugins/medlit-cli/medlit/pubmed/mesh.py:19-88`：查询记录并按词面一致性判定。

### 已有观察

- `Aspirin` 返回 `valid`，`Acetylsalicylic Acid` 和 `Home Blood Pressure Monitoring` 返回 `entry_term`。
- `Plozasiran` 返回 `valid`，但树号为 `@323353`，当前输出没有清楚区分 Descriptor 与 Supplemental Concept。
- 16 题 smoke 中，36 个候选仅 6 个 `valid`、1 个 `entry_term`；MeSH/no-MeSH 的 top-10 相同，R@500 分别为 0.518 和 0.619。小样本结果不支持将当前 MeSH 路径设为默认，也不能据此断言 MeSH 对其他数据无效。

### 评估与处理

- 词表级使用年度 [MeSH XML](https://www.nlm.nih.gov/databases/download/mesh.html)，评估首选词、入口词、Unique ID、记录类型和 fallback。
- 语境级可使用 [NLM-Chem](https://ftp.ncbi.nlm.nih.gov/pub/lu/NLMChem/)、[BC5CDR](https://ftp.ncbi.nlm.nih.gov/pub/lu/BC5CDR/) 和 [NCBI Disease Corpus](https://www.ncbi.nlm.nih.gov/research/bionlp/Data/disease/)。当前 validator 不接收上下文，应预期其对歧义名称存在能力上限。
- 后续实现至少应返回 Unique ID、记录类型、首选词、入口词、Scope Note 和树分类；歧义映射应拒绝或要求确认。
- 未经核验的模型候选不得直接添加 `[MeSH Terms]`。MeSH 继续保持实验开关，待默认 query 构建完成后再决定投入优先级。

## 问题三：全文获取来源覆盖不足

### 问题陈述

当前 `localize-fulltext` 的顺序是 PMCID 转换、Europe PMC XML、Europe PMC PDF、Unpaywall PDF，最后回退 PubMed 摘要。PMCID 不是免费全文的必要条件；PubMed `Full text links`/LinkOut 还会指向出版社和机构仓储。

PMID `35986737` 没有 PMCID，却被 PubMed 标记为 `Free article`，全文入口位于 Elsevier。当前实现不读取 LinkOut、不下载出版社免费 HTML；Unpaywall 还要求配置邮箱且只尝试 `best_oa_location.url_for_pdf`。现有“全文命中率”因此只覆盖 PMC/Europe PMC 和部分 Unpaywall PDF。

`Free article` 只证明存在免费网页入口，不等于具备开放许可证、允许批量下载或存在稳定 PDF。系统不得通过绕过登录、付费墙、验证码或反自动化措施提高命中率。

### 开发方案

- 将 PMC/Europe PMC、Unpaywall 全部 OA locations、PubMed LinkOut、DOI/出版社落地页实现为独立适配器。
- 统一记录候选 URL、内容格式、访问类型、许可证、最终 URL 和失败原因。
- 按 XML、公开 HTML、明确可下载 PDF 的顺序尝试，补齐当前已预留但没有实现的 HTML 下载路径。
- 出版社适配器只处理无需登录且可直接公开访问的内容，并限制跳转、文件大小、Content-Type 和请求频率。
- 自动获取失败时，向用户返回 PubMed 页面及其出版社/仓储入口，说明失败类型，由用户通过浏览器或机构权限访问。
- manifest 区分 `open_access`、`free_to_read`、`subscription_or_login`、`automation_blocked`、`license_unknown` 和 `unavailable`。

专项测试使用 `free full text[sb]` 且无 PMCID 的记录，比较 LinkOut 发现率、公开访问率、下载率、解析率和许可证识别率。PMID `35986737` 作为首个回归样例。

## 问题四：跨文献答案综合尚未形成闭环

### 问题陈述

BioASQ 的 summary、list 和部分 yes/no 问题需要从多篇论文中汇集互补或冲突证据，再形成答案。正确召回论文并不等于完成问题回答。

当前多 lane 检索和 RRF 只负责候选召回与排序；`EvidenceExtractor` 按论文分别抽取启发式证据；`report` 依次写入证据条目，不会跨论文合并结论、处理冲突、评价证据强弱或生成经过医学核验的答案；`verify` 只检查引用和本地来源完整性。

### 开发与评估方向

- 新增独立的 evidence synthesis 阶段，按问题子结论聚合多篇证据。
- 每项结论保留对应 PMID、来源粒度、研究类型、支持或反对方向以及一致或冲突状态。
- 检索阶段单独评价 Recall@K 和 MAP；回答阶段按 BioASQ exact/ideal answer 评价，并增加引用覆盖率、结论可追溯性和冲突呈现检查。
- 在该能力完成前，报告必须标记为逐篇证据汇总，不得表述为已经完成跨文献医学结论验证。
