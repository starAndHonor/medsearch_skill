# 0915 检索可靠性优化

保持模型查询策略、单查询接受机制与PubMed原始排名不变。没有启用摘要筛选、重排或Science迁移副本。

| 已实现 | 行为 |
|---|---|
| 反馈完整性 | 明确区分未返回记录和已返回但无摘要；缺失不再静默 |
| 单独恢复 | recover-feedback只获取缺失反馈，不重跑搜索或补位 |
| 尝试审计 | 网络请求前记录running；失败保留api_failed/network_failed、查询及耗时 |
| 原始响应 | 成功尝试保留ESearch JSON和首次反馈EFetch XML |
| 仅检索模式 | init --mode retrieval；接受查询后推荐导出，不要求全文/报告 |
| 导出封存 | export-retrieval检查排名，导出结果、state快照、完整性检查、SHA-256；拒绝覆盖目录 |
| 瞬时错误恢复 | 429/500/502/503/504有限重试；原先立即失败的500可恢复 |
| 主动限速 | 当前进程内NCBI与Europe PMC请求按服务间隔执行，缓存命中不请求网络 |

旧state默认research模式；原init和下游接口继续可用。切换接受查询会清除导出标记。

限制：限速不是跨进程协调；pubmed_queries统计搜索命令尝试而非HTTP传输重试。恢复后的XML未作为独立原始文件封存。导出清单仅覆盖导出目录中的结果与快照，不自动封存外部批量实验日志或填充模型标识。结构化查询决策、默认精简展示及完整缓存来源追踪尚未实施，以免同时改变行为。新增功能属于可靠性改善，不宣称MAP已经提高。

验证：21项单元测试（含模拟500恢复、反馈恢复、失败审计、模式终点、导出哈希与拒绝覆盖），插件及Skill校验。尚未运行新一轮在线16题冒烟。

独立测试请使用新线程、新state与新导出目录。最简链路：init --mode retrieval → search-pubmed → 必要时recover-feedback → accept-query → export-retrieval。旧实验及官方评估源码不变。
