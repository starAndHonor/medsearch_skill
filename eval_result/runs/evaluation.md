# 新检索流程盲测评估

## 结论

16 道题共执行 19 次 PubMed 搜索，全部成功接受一个 query；其中 13 题首轮接受，3 题因零结果重试后接受。流程已经体现了 Agent 自主构造、查看反馈、顺序重试和选择 query 的设计，没有执行多 lane 或 RRF 融合。

本轮没有读取答案或 gold PMID，因此只能评估流程行为和检索式质量风险，不能据此计算真实召回率或 benchmark 分数。

## 已验证的问题

- **完整 query 可直接执行**：所有 query 均通过语法检查，PubMed 返回了 query translation、结果数、PMID 排名和摘要反馈。
- **零结果可以触发重试**：3 题首轮为 0，重试后分别得到 59、32、147 条结果，说明 Agent 能根据结果反馈放宽过窄条件。
- **顺序尝试状态正常**：重试使用 `q002`，最终通过 `accept-query` 选择单一 query，未将不同 query 的结果混合。
- **实体法对专名问题有效**：RankMHC、Eiffel-by-Night Sign、UCHL1 和 CRELD1 等问题首轮结果较集中，返回的前几篇记录与问题实体直接相关。

## 暴露出的风险

- **接受标准偏宽**：factoid_03、list_04、summary_03 和 factoid_02 分别返回 1415、962、1686 和 434 条结果，但均未继续收缩 query。结果数量非零不能代表检索质量合格。
- **自然语言短语过于字面化**：`high expression`、`PARP inhibition`、`respiratory measurement`、`disease severity` 等词组同时设为 AND 条件，造成 3/16 题首轮零结果。
- **放宽后可能过度泛化**：yesno_01 的重试 query 只保留 WEE1、PARP、resistance，结果虽增加到 59 条，但前几篇是较宽泛的综述；yesno_03 放宽到 respiratory/severity 后得到 147 条，也出现泛化风险。
- **反馈利用仍不充分**：当前 Agent 主要依据“零结果”决定重试，对结果过宽、前几篇主题偏离、同义词覆盖不足等情况没有形成一致的二次查询规则。
- **时间口径未固定**：本轮搜索未设置 `max_date`，结果可能包含 benchmark 发布后的 PubMed 记录。真实流程测试可以保持实时，但与历史 benchmark 分数比较时必须单独固定时间边界。

## 下一步

1. 继续保留当前 Agent 直接生成完整 query 的方式。
2. 在 Skill 中补充“结果过宽也应复查”的判断：结合返回数量、前 10 篇标题/摘要主题一致性和问题实体覆盖决定是否重试。
3. 将零结果、结果过宽和前排主题偏离分别记录，作为后续 query 失败类型，而不是只记录是否有结果。
4. 本轮不进入全文链路；待检索层稳定后，再使用独立评分脚本对这 16 题进行 gold PMID 评估。
